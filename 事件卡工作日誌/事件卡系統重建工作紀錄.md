# 事件卡系統重建工作紀錄

> **歷史工作紀錄。** 本文保留重建過程與舊的「四張／四家依序回應」設計。現行版本已改為
> 每三回合只抽一張共享事件，隨機選出符合條件的受影響陣營；該陣營回應後，事件在全局完成。
> 現行卡表與規則以 `cards/README.md` 及兩份 cards JSON 為準。

2026-08-14。上一份《事件卡系統移除工作紀錄》把舊的 116＋19 張事件卡整套拆掉，
這一份記錄的是重建：資料改由《1926-1928 全球大事事件卡設計稿_v2》第一至六區塊產出，
前端不做「抽卡」動作，改成每三回合直接跳出一張民國老報紙。

## 一、規則

- **每三回合**（第 3、6、9⋯回合）自動抽 **4 張**事件卡。
- **抽出**順序固定 **奉 → 直 → 五 → 國**：第一張歸奉系、第二張歸直系，依此類推。
  這個歸屬會顯示在報紙上，也決定表態卡的建議回應順序。
- **四張全部結算完畢後**，該回合的金錢、工廠、債務才會結算，玩家才能開始行動。
- 抽過的卡不再洗回牌庫：29 張撐約 7 個週期，抽完就不再發報。

### 回應順序（`draw_rules.strict_response_order = true`，現行）

回應嚴格照 **奉 → 直 → 五 → 國**。一般事件由抽到該卡的玩家回應；需要所有勢力表態的卡
（〈亞克斯搜查案〉〈非戰公約〉）以抽到該卡的玩家為第一個回覆者，其餘照上述順序輪流，
**每一家的選擇只作用在自己身上**，同一張卡全部回應完才換下一張。

順序鎖住之後會有「輪到的不是我現在這一家」的問題，所以**報紙右上角自帶一個陣營選擇欄**：
下拉選單列出四家，該回應的那一家後面標「←應由此家回應」，選過去之後按鈕就可以點，
主畫面上方的陣營選單也會同步跟著換。**四張全部結算完，報紙整份清空、這個選擇欄一併消失**，
換陣營回歸主畫面上方的選單，直到下次發報才再出現。

另有一套寬鬆模式留在程式裡：把 `strict_response_order` 改成 `false`，單純事件變成任何一家
點閱都算數、表態卡四家不拘先後。引擎與前端都認這個旗標，改資料就會切換。

## 二、資料

`cards/data/event_cards.json`（版本 `experimental-1.1`，38 張）。內容全部取自
`事件卡工作日誌/1926-1928 全球大事事件卡設計稿_v3.md` 的第一至八區塊：
政治 7、外交 7、文化 4、藝術 4、體育 3、商業 4、學術 4、科技 5。
第九區塊之後（中國藝文／學術／商業界共 15 張）尚未收錄。

v3 相對 v2 只有兩處差異，兩處都已跟進：〈棉花俱樂部〉補上「控制上海或天津者此卡才會
進入牌庫」的進入條件；〈官費留學生〉的效果從「付 15 元、3 回合後生效」改成「解鎖
〈公費留學生〉功能卡」。

每張卡的欄位：

| 欄位 | 內容 |
| --- | --- |
| `id` / `ref` / `name` | 卡片代號、設計稿編號（如 `2.3`）、卡名 |
| `category` | 沿用舊四分類：`foreign_power`／`economic`／`npc_or_other_force`／`security` |
| `power_note` | 設計稿類別後面的括號註記（日、蘇、英／蘇⋯） |
| `effect` | 設計稿的效果全文，原樣搬進來，報紙上的「本報附誌」就是它 |
| `condition` | 設計稿有寫「條件」的兩張才有 |
| `newspaper.headline` / `newspaper.paragraphs` | 新聞仿寫的標題與正文段落 |
| `resolution` | `acknowledge`（我知道了）或 `choice`（附 `options`，每個選項有 `label`、`effect_text`、`apply`） |
| `entry_condition` | 進入牌庫的條件，例如 `{"controls_province": "江蘇"}`、`{"controls_cities_any": ["shanghai"]}` |
| `apply` | 引擎接得住的機械化效果；接不住的寫在 `apply.notes`，報紙上以「※」標出 |

### 進入條件與 scope

四張卡帶 `entry_condition`：〈棉花俱樂部〉（控制上海或天津）、〈中央研究院〉（控制江蘇）、
〈殷墟第一鏟〉（控制河南）、〈跨洋長途電話〉（控制上海）。抽卡時只從「現在有人符合條件」的
卡裡抽；抽到之後如果排到的那一家不符合，會改發給符合的人（照 奉 → 直 → 五 → 國 取第一個）。
沒有人符合的卡就留在池子裡等局勢改變。

`resolution.scope` 決定效果發給誰、由誰回應：`all_players` 是全場（預設），`drawer` 只發給
抽到的那一家、也只有那一家要回應。〈中央研究院〉〈跨洋長途電話〉〈殷墟第一鏟〉都是 `drawer`。

## 三、報紙格式

`frontend/index.html` 多了 `#newspaperBackdrop` 一層遮罩，樣式在 `frontend/styles.css`
的 `.newspaper*` 一段，內容由 `frontend/app.js` 的 `newspaperMarkup()` 產生。由上而下：

報頭左側是大字「民國報」（字距拉開、雙線分隔），右側小字寫卡片名稱。往下一列是日期與
「本期第 N 則／共 4 則」的進度。再往下是圖片預留區——目前畫的是仿網點印刷的灰框，
中間寫「［圖片待補］」加卡片代號，之後把圖檔以卡片 `id` 命名丟進去即可。圖片區下面
緊接新聞標題，標題下是正文，兩者都用標楷體（`"標楷體", "DFKai-SB", "BiauKai", KaiTi`，
找不到才退回襯線字體）。正文下面是「本報附誌」，寫這張卡對遊戲做了什麼；需要表態的卡
會再多一欄「行動選項」，逐條列出每個選項的後果。最底下是回應區：單純事件只有一顆
「我知道了」，需要表態的卡則列出行動按鈕；輪不到你的時候按鈕反灰並顯示「等待某某回應」，
輪到了就顯示「請閣下裁示」。

報頭右側除了卡名之外還有一個**陣營選擇欄**（`[data-newspaper-faction]`），只在報紙開著時
存在，用來把視角切到該回應的那一家；它與主畫面的 `#playerSelect` 共用 `switchFaction()`，
兩邊永遠同步。報紙收起時 `renderNewspaper()` 會把整份 `innerHTML` 清空，選擇欄隨之消失。

設計稿沿用 Markdown 的 `**粗體**`，報紙上會轉成真的粗體，不會露出星號。

## 四、引擎

`backend/card_engine.py`：

- `next_turn()` 拆成兩半。回合數一到，`_start_event_cycle()` 抽四張、排好回應佇列，
  然後**直接回傳** `{"turn": {"awaiting_events": True}}`——本回合的經濟完全沒跑。
- `_finish_turn()` 是原本 `next_turn()` 的後半段（經濟結算、timed effects、卡池同步）。
  它只在四張都回應完之後才被 `respond_event()` 呼叫。
- `pending_event_view()` 給前端看的當前狀態：第幾則、卡片全文、抽到者、還缺誰
  （`pending_responders`），以及 `strict_order`、`needs_every_faction` 兩個旗標。
- `respond_event(player, choice)` 記錄回應、套用效果；一張結完推進索引，四張結完清空
  `pending_events` 並呼叫 `_finish_turn()`。嚴格模式下檢查是否輪到該玩家，寬鬆模式下
  只擋「同一家重複回應同一張卡」。
- 狀態新增 `event_pool`、`event_history`、`pending_events`、`perk_suspensions`、
  `bank_bans`、`bank_limit_multipliers`、`function_card_overrides`。

`backend/server.py` 多了 `/api/respond-event`；`bootstrap()` 的 `cards` 多了 `event` 一組，
所以前端不必另外抓檔案。`backend/data_store.py` 重新載入 `cards/data/event_cards.json`。

### 第二層選擇（follow_up）

選項可以再帶一層 `follow_up`：玩家點下該選項後，報紙的按鈕列會換成第二排，選完才送出。
目前只有〈殷墟第一鏟〉的「售與洋商」用到——第二排是日、蘇、英、美、法五顆買家按鈕，
外加一顆「改選」可以退回第一層。後端 `respond_event(player, choice, follow_up)` 會驗證
第二層的選擇，沒選就擋下並顯示提示。

### 中央研究院的狀態機

這張卡不是一次性的加成，而是一個跟著江蘇跑的狀態，記在玩家的 `academia_sinica`
（`holder` / `disqualified`）：

- **收編**（抽到並回應）之後，只要**控制江蘇**：每回合工業點 +5，且〈盜賣文物〉從你的
  卡池整個清空、手上那幾張也打不出來。
- **丟掉江蘇**：加成停止，〈盜賣文物〉洗回卡池（張數回到 3）。奪回江蘇則兩者都回來。
- **永久失效**有兩個觸發點：在離開江蘇期間**打出過〈盜賣文物〉**，或在任何時候選過
  〈殷墟第一鏟〉的**「售與洋商」**。一旦失效，`disqualified` 就再也不會翻回來，
  之後奪回江蘇、甚至重新抽到這張卡都不會恢復。

`perk_suspension` 現在不限列強 perk：任何功能卡都能被按住，被按住的卡會立刻從牌庫收走
（手上那幾張留著，但打出時會被 `_validate_card_use` 擋下並說明是哪張事件卡造成的），
`turns` 寫 `null` 就是無期限（中央研究院把〈盜賣文物〉永久收走）。

### 住在前端的效果

有兩張卡的效果落在前端的部隊與將領樹上，由 `applyFrontendEventEffects()` 在你按下回應
按鈕、後端把該卡結算完之後執行：〈五月的政變潮〉替所有玩家的大帥與嫡系（忠誠不變）將領
的部隊各兵種 +1 營（受 100 戰力上限限制），〈貝爾福宣言〉替每位玩家隨機挑一位可變忠誠
將領 +1。另有兩張靠 `timed_flags` 傳到前端：〈非戰公約〉的停戰會擋下移入他方領地與
主動攻擊，〈泳渡海峽的女子〉的三回合窗口讓全軍都吃〈進口盤尼西林〉那套戰後傷兵歸隊。

`perk_suspension` 是接在 `_sync_foreign_deck_cards()` 上的：被停權的卡 `desired` 直接歸零，
還沒抽到的會被收回去，到期後下一次同步又自動洗回來。`card_overrides` 接在
`_card_template()` 上，所以〈盜賣文物〉的收益改寫對所有讀卡的路徑一次生效。

### 8.1 新機制

**`tags` 欄位＋事件卡封鎖（`event_locks`）。** 封鎖與移除從此是兩件事：

- **封鎖**：卡片留在 `event_pool` 裡，封鎖期間 `_start_event_cycle` 跳過它，到期自動又抽得到。
- **移除**：從 `event_pool` 拿掉，不再回來（抽過的卡就是這樣）。

一條封鎖可以指名卡片（`cards`），也可以用標籤＋列強整批封鎖（`tags` + `powers`）。
`power_note` 允許寫成「蘇／德」，`_event_powers()` 會拆開比對。
payload 欄位：`event_lock`（掛封鎖）、`event_unlock`（提前解封）。

**`event_pool_add`。** 取代舊的「抽中機率 +X%」。`event_pool` 允許同一個 id 出現多次，
多一張就是多一份被抽中的機會；`_start_event_cycle` 同一輪不會抽到同一張兩次。

語意是「**每一張**符合的卡各加 N 張」，不是從符合的卡裡挑一張加——
`tags=["軍事"], powers=["日"], copies=1` 的意思是資料檔裡每一張日本 [軍事] 事件卡都各多一張。
指定不到任何卡時**不會假裝成功**，`applied` 會回報 `note: "no matching event cards in data"`。

### 11.1 交戰判定怎麼做的

後端沒有部隊——部隊的位置與交戰狀態都住在 `frontend/app.js`：

- `army.cellKey` → `provinceForArmy(army)` 得到它在哪一省
- `activeBattleForArmy(army)` 查 `activeBattles` 裡 status 為 `pending` / `ongoing` 的場次

所以判定放在前端、結論送給後端，走的是 `riot_garrisons` / `city_garrisons` 那條既有通道：

```js
function contestedProvinces() {          // frontend/app.js
  const provinces = new Set();
  for (const army of allArmies()) {
    if (army?.status === "jailed") continue;
    if (!activeBattleForArmy(army)) continue;   // 沒在交戰就跳過
    const province = provinceForArmy(army);     // 所在地格 → 省份
    if (province) provinces.add(province);
  }
  return [...provinces];
}
```

隨 `next_turn` 送出 → `server.py` 轉給 `ENGINE.next_turn(contested_provinces=...)` →
`set_contested_provinces()` 收下。後端只負責「拿到清單之後怎麼算」：
`_province_combat_penalty()` 在 `_city_economy_for()` 算城市產出時把減損扣掉。
全部脫離接觸後前端回報空清單，減損立即解除。

### 10.7：報導少一段

使用者已大幅改寫），逐卡比對 59 張卡的效果、條件、報紙標題與**每一段**內文。
只有一處出入：10.7 的報紙在 JSON 裡有 6 段、稿裡 5 段——使用者刪掉了我寫的
收尾那段「又按：蔡、陳、李三君，十年前同在此樓共事……」。已把 JSON 砍到 5 段。

### 9.5：真正的坑不在文字，在 fallback

先把三張分支卡的狀態對照表 dump 出來，確認方向沒有反：

```
9.5  《新月》月刊  探測=free_china_educators  未抽出→加張 / 已抽出→延長
10.1 昆明湖        探測=confucian_revival     未抽出→加張 / 已抽出→擴大免疫省份
10.3 《古史辨》     探測=confucian_revival     未抽出→封鎖 / 已抽出→護持失效
```

方向是對的。但翻 `card_engine.py` 時發現真正的問題：

```python
chosen = branch.get(key) or branch.get("otherwise")   # ← 就是這行
```

只要某張卡沒定義該狀態的分支，就會**悄悄改跑「未抽出」那一支**。
目標卡明明已經抽出了，引擎卻去執行「還沒抽出時才合理」的加張或封鎖——
這正是使用者問的語意顛倒，而且不會留下任何跡象。

改成三種狀態各走各的、**不做 fallback**；沒定義就是沒效果，並在 `applied`
裡回報 `has_branch: false`：

```python
key = "if_active" if (drawn and active) else ("if_drawn" if drawn else "otherwise")
chosen = branch.get(key)
applied.append({"kind": "conditional_branch", "probe": probe,
                "drawn": drawn, "active": active, "chosen": key,
                "has_branch": chosen is not None})
```

### 9.5 的三種狀態怎麼分

設計稿 v5 原文寫得很清楚：「若已抽出（**無論效果是否仍生效**），則改為將該效果
再延長 5 回合——因為一次性卡抽過就不會再出現，加張沒有意義。」
所以 `if_drawn` 與 `if_active` 掛**同一個** `extend_effect`。
效果已散時沒有東西可延長，`extend_effect` 回報 `entries: 0`——空轉但誠實，

## 十六、2026-08-19：貿易出口的加成改為增量

### 起因

使用者要求找出所有影響對美／對英貿易出口的事件卡，把「將貿易收入增加**至** `$30`」
這類寫死的句型全部改成「將貿易收入**增加** `$10`」——以增量取代寫死的數字上限。

### 找到兩張

掃 `event_cards.json` 裡所有動到 `trade_export_*` 的 `card_overrides`：

| 卡 | 影響對象 | 原本 | 期限 |
| --- | --- | --- | --- |
| 4.3 杜蘭朵公主 | 蘇／英／法／美（**不含日本**） | `cash_gain: 30` | 2 回合 |
| 9.4 國立藝術院 | 日／蘇／英／法／美（全五張） | `cash_gain: 30` | 永久 |

只有這兩張。1.7 胡佛當選雖然提到「以貿易代替干預」，但那是敘述，
它動的是 [軍事] 事件封鎖與美國戰鬥 perk，沒有碰貿易出口的收益。

### 寫死的絕對值為什麼是 bug 而不只是寫法問題

`_card_template()` 舊的實作是 `card.update(override["fields"])`——**後蓋前**。
兩張卡都生效時，後生效的那張只是把同一個 `30` 再蓋一次，
第二份加成完全消失。玩家看卡面會以為兩份加成該疊起來，實際上永遠是 30，
而且沒有任何提示。這就是使用者說的「嚴格寫死的數字加成上限」。

### 做法

`card_overrides` 新增 `field_deltas`，與既有的 `fields` 並存：

```python
card.update(override.get("fields") or {})                  # 絕對值：後蓋前
for field, amount in (override.get("field_deltas") or {}).items():
    deltas[field] = deltas.get(field, 0) + int(amount)     # 增量：累加
...
for field, amount in deltas.items():
    card[field] = int(card.get(field, 0)) + amount         # 以原始數字為基準
```

增量一律以卡片原始數字為基準加上去，所以**生效先後不影響結果**。
有期限的那份到期自動退場，剩下的增量照算。

兩張卡的 9 個 override 全部由 `fields: {cash_gain: 30}` 改為
`field_deltas: {cash_gain: 10}`，卡面文字同步改成「現金**增加** `$10`」。

| --- | --- | --- | --- | --- |

| 對日本 | $20 | — | +$10 | **$30** |

## 十八、2026-08-19：報紙效果欄的排版修正

### 兩個症狀，同一個根

使用者回報效果欄「字會在奇怪的地方跳掉或換行」「欄位中央有奇怪的分隔線」。
把報紙元件單獨渲染出來截圖一看，兩個症狀出自同一行 CSS：

```css
.newspaper-effect b { display: block; letter-spacing: 4px; border-bottom: 1px solid #b4a482; }
```

這條本來是要修飾「本 報 附 誌」那個標題。問題是 `newspaperInline()` 會把效果文字裡的
`**粗體**` 轉成 `<b>`，於是**每一個行內粗體都變成整行區塊、還各自帶一條底線**。

〈杜蘭朵公主〉的效果因此被切成三段：

```
歐洲與美國一時盛行中國風⋯
2  回  合                      ← 整行 + 一條橫線
內：所有人〈對蘇／對英／對法／對美貿易出口〉每次現金
增  加                          ← 整行 + 一條橫線
$10，且〈盜賣文物〉收益⋯
```

「2 回合**內**」的「內」被推到下一行，「增加」被抽成獨立一行——
這就是「字跳掉」；那兩條橫線就是「欄位中央的分隔線」。

### 修法

1. 標題改用自己的 class `.newspaper-effect-title`，區塊樣式與底線只掛在它身上。
   `.newspaper-effect b` 改成純粹的行內粗體（`display: inline`、字距正常、無邊框）。
2. 條列改成真正的 `<ul>`。原本的拆行規則是 `/\s+-\s+(?=\*\*)/`——
   只認「連字號後面緊接粗體」的條目，所以〈東方會議〉那種
   「- 對日關係 ≥3 者：⋯」完全沒被拆開，四條規則擠成一整段跑馬燈。
   改成 `/\s+-\s+/`，並加上懸掛縮排與 `・` 項目符號。
3. 效果欄改為靠左排（正文段落維持兩端對齊）。這一欄夾雜中文與 `$20～40`、`≥6`
   之類不可斷開的西文串，兩端對齊時排不下的西文串會被推到下一行、留下一整排空隙，
   看起來也像字跳掉。
4. 效果文字裡的換行改為段落界線，讓 11.5 的收尾句「報紙依判定結果擇一刊出」
   不再黏在最後一個條目後面。
5. 「行 動 選 項」欄同步改用同一套標題 class 與條列樣式。

### 順手抓到的資料問題

為了守住第 2 點的拆行規則，加了 `NewspaperEffectTextTests`（4 項），
其中一條檢查「不准用半形 `-` 當減號」——**一寫完就抓到三張卡**：
1.4 一黨之國、3.3 火燒紅蓮寺、11.2 南洋兄弟與英美煙草，
都寫成「關係 -1」而不是全場慣用的全形減號 `−1`。
雖然現行的拆行規則要求連字號**兩側**都有空白、這三處剛好逃過一劫，
但這是等著出事的地雷。已一併正規化（JSON 與設計稿 v5 各改 3 / 6 處）。

另外兩條守門：`**` 與反引號必須成對——落單會吃掉後面整段文字。

這次是 CSS／標記層的修正，Python 測試碰不到畫面。
所以另外寫了一支渲染治具 `/tmp/shot.py`：從 `app.js` 原地切出
