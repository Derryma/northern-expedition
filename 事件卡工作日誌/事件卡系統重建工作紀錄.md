# 事件卡系統重建工作紀錄

2026-08-14。上一份《事件卡系統移除工作紀錄》把舊的 116＋19 張事件卡整套拆掉，
這一份記錄的是重建：資料改由《1926-1928 全球大事事件卡設計稿_v2》第一至六區塊產出，
前端不做「抽卡」動作，改成每三回合直接跳出一張民國老報紙。

## 一、規則

- **每三回合**（第 3、6、9⋯回合）自動抽 **4 張**事件卡。
- **抽出**順序固定 **奉 → 直 → 五 → 國**：第一張歸奉系、第二張歸直系，依此類推。
  這個歸屬會顯示在報紙上，也決定表態卡的建議回應順序。
- **四張全部結算完畢後**，該回合的金錢、工廠、債務才會結算，玩家才能開始行動。
- 抽過的卡不再洗回牌庫：29 張撐約 7 個週期，抽完就不再發報。

### 回應順序：正式版與現行測試版

**正式版（尚未啟用）**：回應要嚴格照 **奉 → 直 → 五 → 國**。一般事件由抽到該卡的玩家
回應；需要所有勢力表態的卡以抽到該卡的玩家為第一個回覆者，其餘照上述順序輪流，
同一張卡全部回應完才換下一張。

**現行測試版（`draw_rules.strict_response_order = false`）**：不鎖順序，避免「報紙跳出來
卻因為上一回合不是結束在該陣營而推不下去」。實際行為是：

- **單純事件**：任何一家點「我知道了」就結束，不必等抽到的那一家。
- **需要各自表態的卡**：四家都要點過才換下一張，但誰先誰後不拘；**每一家的選擇只作用在
  自己身上**，切換陣營後那一家再點自己的選項。已表態的陣營按鈕會反灰，並顯示還缺哪幾家。

把 `cards/data/event_cards.json` 的 `draw_rules.strict_response_order` 改成 `true`，
引擎與前端就會切回正式版的嚴格順序——兩套邏輯都寫在程式裡，靠這個旗標切換。

## 二、資料

`cards/data/event_cards.json`（版本 `experimental-1.0`，29 張）。內容全部取自
`事件卡工作日誌/1926-1928 全球大事事件卡設計稿_v2.md` 的第一至六區塊：
政治 7、外交 7、文化 4、藝術 4、體育 3、商業 4。第七區塊之後暫時忽略。

每張卡的欄位：

| 欄位 | 內容 |
| --- | --- |
| `id` / `ref` / `name` | 卡片代號、設計稿編號（如 `2.3`）、卡名 |
| `category` | 沿用舊四分類：`foreign_power`／`economic`／`npc_or_other_force`／`security` |
| `power_note` | 設計稿類別後面的括號註記（日、蘇、英／蘇⋯） |
| `effect` | 設計稿的效果全文，原樣搬進來，報紙上的「本報附誌」就是它 |
| `condition` | 設計稿有寫「條件」的兩張才有 |
| `newspaper.headline` / `newspaper.paragraphs` | 新聞仿寫的標題與正文段落 |
| `resolution` | `acknowledge`（我知道了）或 `choice`（附 `options`，每個選項有 `label`、`effect_text`、`apply`） |
| `apply` | 引擎接得住的機械化效果；接不住的寫在 `apply.notes`，報紙上以「※」標出 |

## 三、報紙格式

`frontend/index.html` 多了 `#newspaperBackdrop` 一層遮罩，樣式在 `frontend/styles.css`
的 `.newspaper*` 一段，內容由 `frontend/app.js` 的 `newspaperMarkup()` 產生。由上而下：

報頭左側是大字「民國報」（字距拉開、雙線分隔），右側小字寫卡片名稱。往下一列是日期與
「本期第 N 則／共 4 則」的進度。再往下是圖片預留區——目前畫的是仿網點印刷的灰框，
中間寫「［圖片待補］」加卡片代號，之後把圖檔以卡片 `id` 命名丟進去即可。圖片區下面
緊接新聞標題，標題下是正文，兩者都用標楷體（`"標楷體", "DFKai-SB", "BiauKai", KaiTi`，
找不到才退回襯線字體）。正文下面是「本報附誌」，寫這張卡對遊戲做了什麼；需要表態的卡
會再多一欄「行動選項」，逐條列出每個選項的後果。最底下是回應區：單純事件只有一顆
「我知道了」，需要表態的卡則列出行動按鈕。現行測試版按鈕一律可點，左下角的提示會寫
「任一勢力點閱即可」或「各勢力分別表態，尚待某某」；自己那一家表態過之後按鈕才反灰，
改顯示「貴方已表態，尚待某某表態」。

設計稿沿用 Markdown 的 `**粗體**`，報紙上會轉成真的粗體，不會露出星號。

## 四、引擎

`backend/card_engine.py`：

- `next_turn()` 拆成兩半。回合數一到，`_start_event_cycle()` 抽四張、排好回應佇列，
  然後**直接回傳** `{"turn": {"awaiting_events": True}}`——本回合的經濟完全沒跑。
- `_finish_turn()` 是原本 `next_turn()` 的後半段（經濟結算、timed effects、卡池同步）。
  它只在四張都回應完之後才被 `respond_event()` 呼叫。
- `pending_event_view()` 給前端看的當前狀態：第幾則、卡片全文、抽到者、還缺誰
  （`pending_responders`），以及 `strict_order`、`needs_every_faction` 兩個旗標。
- `respond_event(player, choice)` 記錄回應、套用效果；一張結完推進索引，四張結完清空
  `pending_events` 並呼叫 `_finish_turn()`。嚴格模式下檢查是否輪到該玩家，寬鬆模式下
  只擋「同一家重複回應同一張卡」。
- 狀態新增 `event_pool`、`event_history`、`pending_events`、`perk_suspensions`、
  `bank_bans`、`bank_limit_multipliers`、`function_card_overrides`。

`backend/server.py` 多了 `/api/respond-event`；`bootstrap()` 的 `cards` 多了 `event` 一組，
所以前端不必另外抓檔案。`backend/data_store.py` 重新載入 `cards/data/event_cards.json`。

## 五、已經自動化的效果

| 能力 | 說明 | 用到的卡 |
| --- | --- | --- |
| `relations` | 對某國關係增減 | 五月的政變潮、一黨之國、婦女選舉權法案、胡佛當選、非戰公約、亞克斯搜查案 |
| `conditional_relations` | 依關係區間分層增減 | 東方會議 |
| `unlock` | 解鎖功能卡（技術三張的前提旗標） | 有聲影戲、無線電網、A 型車問世 |
| `card_copies` | 直接把 N 張功能卡洗進牌庫 | 包浩斯新校舍、柏林密約 |
| `perk_suspension` | 把指定 perk 卡暫時抽離卡池，到期自動回來 | 昭和改元、大英總罷工、托洛茨基的敗北、胡佛當選、亞克斯搜查案、佛州地產崩、昭和金融恐慌 |
| `bank_ban` | 指定銀行停止新放款 | 大英總罷工、昭和金融恐慌、亞克斯搜查案 |
| `bank_limit_bonus` | 銀行額度永久 +N | 德意志入盟 |
| `bank_limit_multiplier` | 銀行額度暫時打折或放大 | 佛州地產崩、華爾街的多頭 |
| `card_overrides` | 改寫功能卡的數字，可永久可限時 | 飛鳥非鳥案、杜蘭朵公主 |
| `city_output` | 指定城市永久產出加成 | 棉花俱樂部 |

`perk_suspension` 是接在 `_sync_foreign_deck_cards()` 上的：被停權的卡 `desired` 直接歸零，
還沒抽到的會被收回去，到期後下一次同步又自動洗回來。`card_overrides` 接在
`_card_template()` 上，所以〈盜賣文物〉的收益改寫對所有讀卡的路徑一次生效。

## 六、還沒自動化的效果

這些在報紙上以「※」標明，玩家自行遵守；`apply.notes` 是唯一的來源：

- 事件分類標籤（`[軍事]`、`[幫會]`）還沒建立，所以「某國軍事事件暫時移出事件卡池」
  一類的效果無法實作：昭和改元、婦女選舉權法案、胡佛當選、西蒙委員會、芥川之死。
- 抽卡權重修正（德商卡 +3%、日本軍事事件 +2%／+5%）：目前抽卡是等機率隨機取出，
  沒有權重機制。影響德意志入盟、東方會議。
- 部隊直接加兵（五月的政變潮的大帥與嫡系各兵種 +1 營）與將領忠誠（貝爾福宣言）：
  這兩者住在前端的將領樹與部隊資料，事件效果目前只走後端。
- 全場停戰 3 回合（非戰公約）、訓兵費用折抵與鎮壓回合數（火燒紅蓮寺）、
  戰後免費復原一個營（泳渡海峽的女子）、貸款加碼利率（佛州地產崩、昭和金融恐慌）、
  新借款首回合免息（華爾街的多頭）、功能卡失效 5 回合（一黨之國）。

## 七、驗證

- `backend/test_backend.py` 新增 `EventCardTests` 八項：卡池 29 張、第三回合觸發且經濟
  被擋住、抽出順序 F/W/S/N、表態卡四家皆可任意順序回應且擋下重複表態與空選擇、
  單純事件任何一家點閱都算數、acknowledge 卡套用效果、perk 停權會把卡從牌庫收走且
  銀行拒貸、事件改寫功能卡、卡片不重複。全套 181 項通過。
- 既有測試中凡是要推進三回合以上的，改用新的 `advance_turn()` 輔助函式，它會把當回合
  跳出的事件卡自動回應掉。
- 瀏覽器實測（寬鬆模式）：視角在五省聯軍時，抽給奉系與直系的單純事件照樣點得下去；
  〈非戰公約〉四家各自表態（S → F → W → N 依序切換視角），每切一家按鈕就重新可點，
  已表態的那一家反灰；四張結完報紙收起，`turn_log` 才出現該回合的經濟結算。
  報紙開著時蓋住整個畫面，點不到回合按鈕。
