# 事件卡系統移除工作紀錄

紀錄兩次連續的清理：先移除 40 張永遠進不了牌庫的功能卡，再移除整套事件卡與後果卡系統。
兩次的 commit 分別是 `60888d4` 與 `78f6e5c`。

- 移除前：`cards/data/` 四個檔案、功能卡 120 張、事件卡 116 張、後果卡 19 張。
- 移除後：`cards/data/` 兩個檔案、功能卡 80 張，事件卡與後果卡全數刪除。
- 程式碼淨減 3040 行（12 個檔案、49 行新增、3040 行刪除）。

---

## 一、為什麼移除

事件系統從頭到尾沒有啟用過，三個層面都是斷的：

1. **引擎沒開**：`backend/card_engine.py` 的 `FEATURES["events"] = False`，
   `next_turn` 裡抽事件那一行被這個旗標擋住，所以自動抽事件從來沒發生過。
2. **前端沒有入口**：`/api/draw-event` 這個端點存在，但 `frontend/app.js` 與 `index.html`
   從頭到尾沒有呼叫它。所有事件 UI（徽章、彈窗、歷史面板）都掛在
   `bootstrap.features.events` 這個永遠為 false 的旗標下，等於永遠隱藏。
3. **後果卡幾乎沒有觸發來源**：19 張後果卡裡只有 1 張（〈舊軍閥索取地盤〉）真的被功能卡
   的 `generated_event_cards` 指到；其餘 18 張靠的是 `enters_pool_when` 欄位，
   而那個欄位**全專案沒有任何程式讀取**。

結論是：這套資料只會讓卡池裡混進永遠不會出現的卡，維護時還要一直繞過它。

## 二、各檔案的功能、歸屬與連接口

### `cards/data/event_cards.json`（已刪除，116 張）

**功能**　全域自動事件牌堆。設計上每回合自動抽一張，代表全國或國際局勢變化，
可能同時影響所有玩家。

**歸屬**　資料由 `backend/data_store.py` 載入，執行期完全歸 `backend/card_engine.py` 管；
前端只是被動接收 bootstrap 裡的副本。**這些卡沒有任何 `mechanic` 欄位**，
也就是說引擎從來沒有實作過它們的效果，`effect` 只是給人看的敘述文字。

**檔案結構**

| 欄位 | 說明 |
| --- | --- |
| `version` / `count` / `cards` | 頂層三個鍵 |
| `id` / `name` | 卡片識別與名稱 |
| `deck_type` | 一律 `"event"` |
| `category` | `foreign_power` 35、`npc_or_other_force` 35、`economic` 33、`security` 13 |
| `source` | 素材出處，多數指向 `PJ Boardgame/北伐風雲_整合遊戲介面.html` |
| `status` | `active` 112 張、`retired` 4 張（南滿鐵路交涉、關東軍特別演習、濟南護僑要求、英國海軍示威） |
| `foreign_power` / `npc_faction` | 對象標記 |
| `effect` | 敘述文字，引擎不解析 |
| `base_weight` | 加權抽卡用的權重 |
| `requirement_expression` / `conditions` | JS 風格的條件字串（例如 `s.jp>=5`、`s.pv.滿洲`），**引擎沒有實作求值器**，只是從 PJ 素材帶過來的備註 |

**連接口（全部已移除）**

| 位置 | 原本做什麼 |
| --- | --- |
| `data_store.DATA_PATHS["event_cards"]` | 載入檔案 |
| `data_store` 的 `indexes["event_cards"]` | 建 id → 卡片索引 |
| `data_store` 的 `metadata["event_cards"]` | 回報張數給 bootstrap |
| `card_engine.new_game` 的 `event_ids` | 挑出 `status == "active"` 的 112 張，成為 `state["event_pool"]` 的初始內容 |
| `card_engine.snapshot` 的 `counts["event_pool"]` | 回報牌堆剩幾張 |
| `card_engine.bootstrap` 的 `cards["event"]` | 把整份卡片資料送給前端 |
| `card_engine.draw_event()` | 抽一張、寫進 `event_history` 與 `last_event` |
| `card_engine._weighted_event_choice()` | 依 `base_weight` 從 `event_pool` 加權抽出 |
| `card_engine._card_template()` | 查 id 時會查這個索引 |
| `server.py` 的 `/api/draw-event` | 對外的抽事件端點 |

### `cards/data/injected_event_cards.json`（已刪除，19 張）

**功能**　後果卡。不在任何一副牌裡，而是「打出某張功能卡之後才被塞進事件牌堆」的後續麻煩。

**歸屬**　同樣由 `data_store` 載入、`card_engine` 管理。`status` 一律 `injectable`，
`base_weight` 一律 `0`（進池後才由塞入者決定份數）。同樣**沒有 `mechanic` 欄位**。

**檔案結構**　欄位與事件卡大致相同，差別在多了 `enters_pool_when`（19 張全有）、
少了 `requirement_expression` 與 `conditions`，`foreign_power` 只有 14 張有。
分類為 `foreign_power` 11、`economic` 3、`npc_or_other_force` 3、`security` 2。

**連接口（全部已移除）**

| 位置 | 原本做什麼 |
| --- | --- |
| `data_store.DATA_PATHS["injected_event_cards"]` | 載入檔案 |
| `data_store` 的 `indexes` / `metadata` | 建索引、回報張數 |
| `card_engine.bootstrap` 的 `cards["injected_event"]` | 送給前端 |
| `card_engine.use_function` 的注入迴圈 | 讀功能卡的 `generated_event_cards`，把後果卡按份數同時 append 進 `event_pool` 與 `injected_event_pool` |
| `state["injected_event_pool"]` | 只被 `snapshot` 計數，沒有其他讀取者 |
| `card_engine._card_template()` | 查 id 時會查這個索引 |

**`enters_pool_when` 欄位的真相**　19 張全都有這個欄位，內容看起來像觸發條件
（`function_card:function_橫濱正金銀行借款`、`event_choice:濟南護僑要求 refused`、
`any black_gold function card is used twice by same player`……），
但**全專案沒有任何程式讀取它**。它是從原始素材沿用下來的設計備註。
真正會把後果卡送進池子的只有功能卡的 `generated_event_cards`，
而移除前全部 80 張功能卡裡只有〈在野名將投效〉還帶著這個欄位。

### `cards/data/function_cards.json`（保留，80 張）

**這次的改動**　拿掉所有卡片的 `generated_event_cards` 欄位。
移除前 80 張裡只有〈在野名將投效〉的內容是非空的（指向〈舊軍閥索取地盤〉），
其餘都是空陣列。

### `cards/data/card_pool_rules.json`（保留）

**這次的改動**　版本從 `experimental-0.3` 升到 `0.4`，刪掉兩段：

- `draw_timing.event_cards`：事件卡的抽牌時機（global／automatic／each turn）。
- `dynamic_pool_rules`：三條動態牌池規則（`function_card_used`、`player_decision_on_event`、
  `war_outcome`），描述什麼情況下會往事件池追加卡片。

保留 `draw_timing.function_cards`、`body_guard_state`、`foreign_relation_rules`。
這個檔案由 `card_engine.bootstrap` 原封不動轉發給前端，前端目前沒有讀它，屬於參考資料。

放慢節奏重跑就沒有，畫面也會自行恢復。

## 五、如果之後要把事件系統做回來

需要補齊的東西，按依賴順序：

1. **條件求值器**。事件卡的 `requirement_expression` 與 `conditions[].expression`
   是 JS 風格字串（`s.jp>=5`、`s.pv.滿洲`、`Math.min(s.jp,s.su,s.uk,s.us,s.fr)<=-8`），
   引擎從來沒有實作過求值。這是最大的一塊。
2. **事件效果的 mechanic**。116 張事件卡與 19 張後果卡全都只有敘述文字，
   要像功能卡那樣一張一張補上 `mechanic` 並在 `use_function` 那條 `elif` 鏈裡實作。
3. **玩家選項分支**。相當多事件寫成「接受→…／拒絕→…」，
   現行引擎沒有任何讓玩家在事件上二擇一的機制。
4. **後果卡的觸發條件**。`enters_pool_when` 要嘛實作成真的規則，
   要嘛全部改寫成功能卡的 `generated_event_cards`。
5. **前端事件流程**。抽事件的呼叫點、彈窗、歷史面板都要重做。

刪掉的兩份 JSON 完整保留在 git 歷史裡，`git show 78f6e5c~1:cards/data/event_cards.json`
與 `git show 78f6e5c~1:cards/data/injected_event_cards.json` 可以原樣取回。
同一資料夾裡的《PJ事件卡與功能卡對照.md》另外整理了 PJ Boardgame 那 159 張事件卡的全表
與重疊分析，可以當作重建時的素材清單。
